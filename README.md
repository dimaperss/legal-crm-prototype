# Клиенты юриста — мини-CRM

Прототип для отклика на вакансию LegalTech-платформы «Доступное Право».

## 1. Живой прототип

**https://legal-crm-prototype.netlify.app**

_Реальный отзыв приложу отдельным скриншотом в переписке._

## 2. Что это

Мини-CRM для юриста: одна страница, на которой видно всех клиентов, их статусы и
счётчики по статусам. Юрист сразу попадает на дашборд (без логина), может добавить
клиента (имя, телефон, статус) и вести его по воронке дел: **Новый → В работе →
Закрыт**. Счётчики и таблица обновляются мгновенно, данные хранятся в реальной БД,
а при добавлении клиента юристу приходит уведомление в Telegram.

## 3. Стек и почему именно он

Один файл `index.html` (HTML + CSS + vanilla JS) — максимальная скорость до рабочего
продукта, никакой сборки и зависимостей. **Supabase** (PostgREST + `@supabase/supabase-js`
с CDN) — это настоящая PostgreSQL-база с REST-доступом, а не мокап: данные переживают
перезагрузку и живут на сервере. **Netlify Function** для Telegram — чтобы токен бота
жил в переменных окружения и никогда не светился в клиентском коде; фронтенд дергает
функцию по относительному пути, а секрет остаётся на сервере. Всё вместе деплоится
одним пушем на **Netlify** (статика + функция в одном деплое).

## 4. Как запустить свой инстанс

1. **Supabase.** Создайте проект на [supabase.com](https://supabase.com). В разделе
   **SQL Editor** выполните целиком файл [`supabase_setup.sql`](supabase_setup.sql) —
   он создаст таблицу `clients`, включит RLS с политиками для роли `anon` и добавит
   3 демо-записи.
2. **Ключи.** В **Project Settings → API** возьмите `Project URL` и публичный
   (`publishable` / `anon`) ключ. Впишите их в `index.html` в константы
   `SUPABASE_URL` и `SUPABASE_ANON_KEY` (в этом прототипе они уже подставлены).
3. **Деплой на Netlify.** Подключите репозиторий к [Netlify](https://netlify.com)
   (или перетащите папку в drag-and-drop деплой). Конфиг [`netlify.toml`](netlify.toml)
   уже указывает `publish = "."` и `functions = "netlify/functions"`.
4. **Telegram-бот.** Создайте бота через [@BotFather](https://t.me/BotFather),
   получите токен. Узнайте свой `chat_id` (например, написав боту и открыв
   `https://api.telegram.org/bot<TOKEN>/getUpdates`).
5. **Переменные окружения Netlify.** В **Site settings → Environment variables**
   задайте:
   - `TELEGRAM_BOT_TOKEN` — токен бота;
   - `TELEGRAM_CHAT_ID` — ваш chat_id.

   Передеплойте сайт, чтобы функция подхватила переменные. Если переменные не заданы,
   уведомление просто пропускается (`{ skipped: true }`) и добавление клиента работает
   как обычно.

## 5. Что делал сам, а что делал AI

- **Сам:** продуктовые решения, сценарий, схема данных, приоритизация, ревью и правки,
  деплой, тестирование.
- **AI (Claude Code):** генерация кода по моим промптам.

## 6. Осознанные упрощения прототипа (и что было бы в проде)

Это демо на один день, поэтому сознательно упрощено:

- **Авторизация.** Экрана логина нет — по сценарию юрист сразу видит дашборд. В проде
  здесь была бы аутентификация (Supabase Auth) и RLS-политики по `user_id`: каждый
  юрист видит и меняет только своих клиентов. Сейчас роли `anon` открыты SELECT / INSERT /
  UPDATE — это зафиксированное решение для демо; DELETE не открыт вовсе.
- **Нет пагинации, поиска и фильтров по тексту** — при росте базы понадобятся.
- **Нет редактирования клиента** — можно менять только статус по цепочке.
- **Нет истории смены статусов** (кто и когда перевёл дело) — в проде это отдельная
  таблица-журнал.
- **Нет дедлайнов/напоминаний** — за рамками MVP-сценария.
